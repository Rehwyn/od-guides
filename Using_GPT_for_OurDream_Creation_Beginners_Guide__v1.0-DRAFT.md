# Using GPT for OurDream Creation: A Beginner’s Practical Guide

## Opening note: What this guide is

This guide is for OurDream creators who want to use GPT as a practical creative helper but do not know where to start.

You might have a character idea but not know how to shape it. You might want help with personas, group chats, outfit notes, homes, cities, settings, or reviewing a draft before you publish it. You might have heard people talk about Projects, source documents, prompts, templates, or Custom GPTs and felt like you were already behind before you even began.

You are not behind.

The simplest useful version of GPT-assisted creation is not complicated. You give GPT a messy idea, tell it what kind of help you want, tell it what not to erase, and ask for an output you can actually use. That can be enough to start.

This guide is meant to help you get your first useful results without building a giant system. It focuses on small habits: making one simple Project, writing clearer prompts, using a few helpful source documents, asking GPT to help you improve your prompt, and using GPT as a brainstorming partner, organizer, editor, and reviewer.

The main promise is simple:

> This guide helps OurDream creators set up a simple GPT workspace and use it for practical creative help without losing control of their own ideas.

That last part matters. GPT can be useful, but it is not the author of your character. You are. GPT can suggest directions, find weak spots, organize messy notes, draft options, and help you review what you already made. It should not flatten your idea into something generic just because the generic version sounds smoother.

A rough idea is allowed to stay rough at first. In fact, it often should. If your concept is strange, niche, indulgent, emotionally specific, funny, messy, or hard to explain, that may be the part worth preserving. Do not rush to let GPT polish away the reason you cared about it.

This guide can help with:

* brainstorming character ideas from rough seeds;
* improving a character concept without replacing it;
* making personas for different types of chats;
* planning group chats around specific characters;
* writing compact outfit notes for pinned memories;
* designing homes, cities, rooms, workplaces, fantasy locations, or other settings;
* asking GPT to review a draft for clarity and usefulness;
* creating better prompts when you do not know how to ask for what you want.

This guide is not a full OurDream profile-design manual. It is not a complete prompt-engineering course. It is not a guide to every advanced method, tracker, template, or character-building system someone might use.

You do not need to learn everything at once.

Start with one useful result. Then another. Add structure only when it solves a problem you actually have.


## How to use this guide

## 1. The simplest useful way to start

The easiest way to begin is to make one simple GPT workspace for your OurDream creation work.

You do not need a huge library of files. You do not need a perfect template. You do not need to understand every setting. The first goal is just to make GPT easier to use for repeated creative work.

Think of your first setup like this:

> One Project. One short instruction block. One test chat. One rough idea.

That is enough.

### Your first 15 minutes

Here is a simple first setup path.

1. Make one Project for OurDream creation work.
2. Give it a clear name, such as `OD Creation Help`, `OurDream Character Workshop`, or `Character + Group Chat Helper`.
3. Add a short Project Instruction block.
4. Start a new chat inside that Project.
5. Give GPT one rough idea and ask for brainstorming, not a full finished profile.

The point is not to create a perfect system. The point is to get one useful result and learn from it.

### A simple Project Instruction block

Project Instructions are the standing guidance you want GPT to remember while working in that Project. For a beginner setup, keep them short. You can always improve them later.

Here is a starter version:

```text
Help me brainstorm, organize, draft, and review OurDream creation material. Preserve my creative intent. Do not replace my idea with something generic. Keep adult fictional roleplay discussion non-graphic and policy-compliant.
```

That is enough for a first version.

It tells GPT:

* what kind of work you are doing;
* that you want creative help;
* that your own idea should be preserved;
* that the work should stay appropriate for a general GPT workspace.

You can add more later, but avoid turning your Project Instructions into a giant rulebook on day one. If the instructions get too long, they become harder to maintain and easier to contradict.

A better beginner habit is to keep Project Instructions simple and put specific templates, examples, checklists, or notes into source documents later.

### Your first test chat

Once the Project exists, start with a rough idea. Do not wait until you have a polished concept.

For example:

```text
I’m making an OurDream character from this rough seed:

A goth vampire college student, but I don’t want her to feel like the generic version.

Help me brainstorm 5 different directions for her. First identify what is most important to preserve from the seed. Do not draft the full profile yet.
```

This is a good beginner prompt because it does not ask GPT to do everything at once. It asks for directions before a full draft. It also tells GPT what not to lose: the goth vampire college student seed.

That kind of instruction matters. If you only say “make me a vampire girl,” GPT may give you the most obvious version of the idea. If you say “preserve this seed, but help me make it less generic,” GPT has a better job to do.

### Aim for one useful result

A first GPT session does not need to produce a finished character.

A useful first result might be:

* five possible versions of the character;
* a list of what makes the idea interesting;
* a few questions that reveal what is missing;
* a cleaner summary of your messy notes;
* a short review of what feels generic;
* a starter setting or opening situation.

That is success.

Beginners often ask GPT for a full final character too early. Sometimes that works, but often it skips the most useful part: figuring out what the character is actually about.

A safer early workflow is:

1. brainstorm;
2. choose a direction;
3. ask for a plan;
4. draft one piece;
5. review it;
6. revise.

You do not have to follow that every time, but it is a good default when you are still learning.

### Add files later

You may eventually want source documents: templates, checklists, style notes, setting files, persona notes, or reusable prompts. Those can be very useful.

But they are not the first step.

Start with a Project and a few good chats. Once you notice yourself repeating the same instructions, then consider turning those repeated instructions into a small source document.

For example, if you keep telling GPT, “Please preserve the weird part of my idea and give options before rewriting,” that might belong in your Project Instructions.

If you keep using the same character checklist, that might become a source document.

If you keep reusing the same outfit-note format, that might become a template.

Add structure when it saves effort, not because someone else has a more complex setup.

## 2. Chat, Project, or Custom GPT?

There are a few different ways to use ChatGPT. You do not need to master all of them before starting.

For most OurDream creators, the easiest default is:

> Use a normal chat for quick one-off help. Use a Project for ongoing creation work. Consider a Custom GPT later if you want a specialized reusable assistant.

Here is the beginner version.

| Tool        | Best for                                                                    | Beginner recommendation           |
| ----------- | --------------------------------------------------------------------------- | --------------------------------- |
| Normal chat | Quick one-off questions, simple brainstorming, trying GPT without setup     | Good for experimenting            |
| Project     | Ongoing creative work with related chats, instructions, and reference files | Best default starting point       |
| Custom GPT  | A specialized assistant with its own instructions, knowledge, and behavior  | Useful later, not necessary first |

### Normal chat

A normal chat is the simplest way to use GPT. You open a chat, ask for help, and continue from there.

This is good for:

* asking a quick question;
* testing whether GPT can help with a rough idea;
* rewriting a short paragraph;
* brainstorming a few names;
* getting a quick explanation.

A normal chat is often enough for small tasks.

Example:

```text
Give me 10 possible names for a cozy witch cafe setting. Make them warm, slightly magical, and not too silly.
```

No Project needed. No setup needed. Just ask.

The downside is that a normal chat is usually less organized for ongoing work. If you are making multiple characters, saving templates, building settings, or repeatedly asking for OD-specific help, you may want a Project.

### Project

A Project is better for a continuing creative workspace. It can keep related chats together and can use project-level instructions and reference material. That makes it a good fit for OurDream creation work because character design often involves multiple passes.

A Project is useful when you want GPT to help with:

* several characters over time;
* repeated character planning;
* source documents or templates;
* a consistent creative preference note;
* a recurring setting or world;
* group chat planning;
* draft review and revision;
* collecting reusable prompts.

For example, you might have one Project called `OD Creation Help`. Inside it, you could have separate chats for:

* character brainstorming;
* persona drafting;
* group chat planning;
* outfit notes;
* setting design;
* prompt improvement;
* reviewing drafts.

The Project does not need to be complicated. It is mostly a way to keep related work in one place.

For beginners, this is usually the best starting point because it gives you more continuity than a normal chat without requiring you to build a whole custom assistant.

### Custom GPT

A Custom GPT is a more specialized assistant. It can have its own instructions, knowledge, and capabilities. That can be powerful if you want a reusable helper designed for one specific purpose.

For example, someone might make a Custom GPT for:

* image prompt drafting;
* public description review;
* outfit-note generation;
* character brainstorming;
* a specific writing workflow.

Custom GPTs can be useful, especially if you want to reuse the same assistant repeatedly or share it with other people. But they are not necessary for a beginner.

If you are just starting, a Custom GPT may be more setup than you need. A Project is usually easier because you can start casually, make normal chats, add a few files, and adjust as you learn.

### Which should you choose first?

Use this quick rule:

* If you have one quick question, use a normal chat.
* If you are doing ongoing OurDream creation work, use a Project.
* If you later want a specialized reusable assistant, consider a Custom GPT.

For most creators reading this guide, start with a Project.

That gives you enough structure to be useful without forcing you to design a whole system before you know what you need.

The important thing is not choosing the “perfect” tool. The important thing is starting with a setup that helps you create instead of making you feel stuck.

A Project with simple instructions and one rough character chat is already enough to begin.

## 3. Project Instructions vs source documents

Once you have a Project, the next useful thing to understand is the difference between Project Instructions, source documents, and the prompt you type in the current chat.

These three things work together, but they do different jobs.

In this guide, I use “source document” to mean any file, note, checklist, template, or reference material you want GPT to use. The exact UI wording may vary.

The beginner version is:

> Project Instructions tell GPT how to help.
> Source documents give GPT material to use.
> Your prompt tells GPT what to do right now.

If you understand that distinction, a lot of GPT setup starts to make more sense.

### The simple comparison

| Piece                | What it does                                              | Good examples                                                                                    |
| -------------------- | --------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| Project Instructions | Stable guidance for how GPT should behave in this Project | “Preserve my creative intent,” “Help with OurDream creation work,” “Keep outputs easy to revise” |
| Source documents     | Reference material GPT can use when relevant              | Templates, checklists, setting notes, style preferences, reusable prompts, examples              |
| Current prompt       | The task you want GPT to perform right now                | “Use my checklist to brainstorm this character,” “Review this draft,” “Make an outfit note”      |

Think of it like working with a creative assistant.

Project Instructions are how you generally want the assistant to work with you.

Source documents are the notebook, checklist, template folder, or reference binder you give them.

The prompt is the specific task you ask for today.

### What belongs in Project Instructions?

Project Instructions should be short, stable, and broadly useful across many chats in the Project.

They are a good place for things like:

* what kind of work this Project is for;
* how you want GPT to treat your ideas;
* whether you prefer brainstorming, drafting, review, or concise output;
* recurring style preferences;
* broad boundaries for the workspace.

For example:

```text
Help me brainstorm, organize, draft, and review OurDream creation material. Preserve my creative intent. Do not replace my idea with something generic. Keep adult fictional roleplay discussion non-graphic and policy-compliant.
```

That is a good beginner instruction block because it tells GPT the main job without trying to explain every possible task.

You can add more later, but try not to turn Project Instructions into a giant rulebook. If the instructions become too long, they may become harder for you to maintain and harder for GPT to apply consistently.

A useful rule:

> Put broad, repeated behavior guidance in Project Instructions. Put specific templates and reference material in source documents.

### What belongs in source documents?

Source documents are better for material GPT may need to reference, copy, follow, summarize, or compare.

Good source documents include:

* a basic character checklist;
* a persona template;
* a group chat planning checklist;
* setting notes;
* outfit note templates;
* your personal preferences;
* a list of reusable prompts;
* examples of public descriptions or greetings you like;
* notes about a recurring world, city, school, tavern, company, family, or friend group.

Templates usually belong in source documents, not Project Instructions.

For example, if you have a pinned-memory outfit format you want GPT to follow, that should probably be a source document. If you have a character checklist, that should probably be a source document. If you have examples of good profile descriptions, those should probably be a source document.

That keeps your Project Instructions clean and makes your templates easier to update.

### Source documents are not magic

Uploading or adding a source document does not always mean GPT will use it exactly how you expect.

If you want GPT to follow a template, say so in the prompt.

For example:

```text
Use the source document named `Basic Character Checklist` as the structure for this task.

My rough character idea is:

[PASTE IDEA]

Follow the checklist’s section order where relevant. Fill only what can be reasonably inferred from my idea. If something important is missing, mark it as a question instead of inventing major facts.
```

That prompt does a few useful things:

* it names the source document;
* it tells GPT what job the source document has;
* it says how strictly to use it;
* it tells GPT what to do when information is missing.

This matters because a source document can be used in different ways. A checklist might be used as a strict structure, a loose reminder, or a review tool. A template might be followed exactly, adapted lightly, or used only for inspiration. If you care which one happens, say so.

### A simple three-part prompt pattern

When you want GPT to use a source document, try this pattern:

```text
Use `[source document name]` as [template / checklist / reference / example style].

Here is what I’m working on:

[PASTE IDEA OR DRAFT]

Please give me:

[DESIRED OUTPUT]
```

For example:

```text
Use `Outfit Note Template` as the format.

Character: Maren
Scene: winter market date
Style goal: warm, practical, quietly elegant

Please write a compact pinned-memory outfit note.
```

That is much clearer than saying:

```text
Make an outfit for Maren.
```

The second version might still work, but the first version gives GPT a job, a source, and a target format.

### Keep the setup light

The goal is not to build a perfect instruction system. The goal is to make GPT more useful with less repeated explanation.

A good beginner setup might have:

* short Project Instructions;
* one preferences note;
* one character checklist;
* one reusable prompt list;
* one setting or outfit template if you use those often.

That is enough.

You can always add more later.

## 4. What source documents should beginners make first?

Source documents are useful, but only if they solve a real problem.

A common beginner mistake is uploading too much too early: old drafts, huge lore files, half-finished templates, examples, screenshots, notes, research, and random scraps. That can make the Project feel more powerful, but it can also make it harder to use.

Start with a few small files that help with repeated tasks.

The best first source documents are usually:

1. `My OD Preferences`
2. `Basic Character Checklist`
3. `Reusable Prompts`
4. `Setting Notes`
5. `Outfit Note Template`

You do not need all of these on day one. Start with one or two. Add the others when you actually need them.

### `My OD Preferences`

This is usually the best first source document because it helps GPT understand your taste across many tasks.

Use it to record what you like, what you avoid, and how you want GPT to help with your ideas.

What to put in it:

* favorite tones;
* character types you enjoy;
* themes you often like;
* dynamics you often write;
* things you usually avoid;
* how you want GPT to revise your ideas;
* reminders about preserving your creative intent.

What not to put in it:

* every character idea you have;
* private information you do not want in the Project;
* huge lists of random examples;
* full profile templates.

Make this document when:

* GPT keeps making your ideas too generic;
* you keep repeating the same preferences;
* you want GPT to understand your usual style better.

A simple starter version:

```markdown
# My OD Preferences

I like:
- [themes, tones, character types]

I usually avoid:
- [themes, tones, dynamics]

When improving my ideas:
- Preserve the specific or weird part first.
- Suggest options before rewriting.
- Do not make every character safer, softer, or more generic.

For OurDream:
- Help with characters, personas, group chats, outfits, settings, and review.
- Keep discussion non-graphic and policy-compliant in this workspace.
```

This does not need to be perfect. It is a living note. Update it when you notice patterns.

### `Basic Character Checklist`

A basic character checklist helps GPT avoid skipping obvious planning areas.

It does not need to be a full profile template. In fact, for beginners, it probably should not be. A checklist is easier to use than a giant field-by-field profile structure.

What to put in it:

* character seed;
* core appeal;
* roleplay promise;
* personality;
* motive;
* voice;
* relationship or user role;
* setting;
* first scene idea;
* what should stay flexible;
* questions to answer later.

What not to put in it:

* a huge advanced profile template;
* strict rules you do not understand yet;
* every OurDream field detail;
* long theory about character design.

Make this document when:

* your character ideas feel scattered;
* GPT keeps jumping straight to a full draft;
* you want a repeatable planning structure.

A useful checklist helps GPT ask better questions and organize your ideas before drafting.

### `Reusable Prompts`

This is exactly what it sounds like: a place to save prompts that worked.

A lot of GPT use improves through repetition. When a prompt gives you a good result, save it. Later, you can reuse it, tweak it, or ask GPT to improve it.

What to put in it:

* character brainstorm prompts;
* review prompts;
* persona prompts;
* group chat planning prompts;
* outfit prompts;
* setting prompts;
* meta-prompts;
* prompts that tell GPT how to use a source document.

What not to put in it:

* every prompt you ever tried;
* long chat transcripts;
* prompts that failed unless you add a note explaining why;
* five near-identical versions of the same prompt.

Make this document when:

* you find yourself scrolling back through old chats to copy a prompt;
* you have 3–5 prompts you know you want to reuse;
* you want a simple personal prompt library.

A good reusable prompt file can stay short. Ten good prompts are better than fifty messy ones.

### `Setting Notes`

Setting notes help when your characters share a world, city, home, school, workplace, tavern, guild, neighborhood, spaceship, apartment building, or other recurring place.

Use this file to help GPT keep the setting consistent without turning every chat into a lore dump.

What to put in it:

* important locations;
* tone and genre;
* recurring social spaces;
* who lives or works there;
* what kinds of scenes the setting supports;
* flexible details GPT may invent;
* protected details GPT should not change.

What not to put in it:

* unrelated lore;
* long backstory that never affects play;
* every possible room, street, shop, and NPC;
* details you are not ready to treat as stable.

Make this document when:

* multiple characters use the same place;
* you want homes/settings to feel consistent;
* you keep asking GPT to recreate the same location.

A strong setting note should answer: “What can happen here?”

For roleplay, that is usually more useful than a long encyclopedia entry.

### `Outfit Note Template`

An outfit note template is useful if you make pinned memories for outfits, scenes, seasons, events, or alternate looks.

This does not need to be fancy. It just needs to help GPT produce consistent, compact notes.

What to put in it:

* clothing;
* colors and materials;
* accessories;
* hair or makeup if relevant;
* scene or season;
* how the outfit affects the character’s presence;
* any details that should stay consistent.

What not to put in it:

* full image-prompting theory;
* ten paragraphs of visual description;
* details that do not matter in chat;
* every outfit the character might ever wear.

Make this document when:

* you often create outfit pinned memories;
* you want a consistent outfit-note shape;
* you want GPT to help with seasonal, event, or scene-specific looks.

A useful outfit note is compact enough to use and specific enough to matter.

### Optional later source documents

After the first few files, you may eventually add more.

A `Persona Template` can help if you make multiple personas.

A `Group Chat Planning Checklist` can help if you often build group chats around selected characters.

An `Image Prompting Notes` file can help if you start using GPT for image prompts, reference descriptions, or plain-language visual planning.

These are later upgrades. Do not make them just because they sound useful. Make them when you notice yourself doing the same task more than once.

### The rule for adding new source documents

Before adding a new source document, ask:

> Will I use this more than once?

If the answer is no, it may not need to be a source document. It can just be part of the current chat.

Ask:

> Does this help GPT do a recurring job better?

If yes, it may be worth saving.

Ask:

> Is this file clear enough that GPT can tell what it is for?

If no, clean it up before relying on it.

Good source documents do not need to be long. They need to have a clear job.

## 5. File formats GPT can read and work with

GPT works best with files that are clean, readable, and organized.

ChatGPT features, file support, and UI labels can change. Treat this section as practical working advice, not a permanent list of supported formats. Before publishing or relying on exact product details, check the current ChatGPT Help pages.

For everyday beginner use, the practical advice is simple:

> Use common document formats, keep the file clean, and export Google Docs before uploading if needed.

### Useful file formats

| Format  | Best for                                                       | Beginner notes                                                      |
| ------- | -------------------------------------------------------------- | ------------------------------------------------------------------- |
| `.txt`  | Plain notes, simple lists, quick references                    | Very simple and reliable, but has little formatting                 |
| `.md`   | Clean headings, lightweight structure, templates, prompt lists | Great for readable source docs if you are comfortable with Markdown |
| `.docx` | Google Docs or Word-style guide documents                      | Good for polished text documents and shared drafts                  |
| `.pdf`  | Preserved layout, exported guides, reference documents         | Useful when layout matters, but harder to edit after export         |
| `.csv`  | Simple tables, lists, indexes                                  | Good for structured data, tags, character lists, inventories        |
| `.xlsx` | Larger spreadsheets, tables, trackers, indexes                 | Useful for structured planning, but may be more than beginners need |

For most beginner source documents, `.txt`, `.md`, or `.docx` is enough.

If you write in Google Docs, you may need to export the document before uploading it. Exporting to `.docx` is usually useful when you want GPT to read the text and structure. Exporting to `.pdf` is useful when you want to preserve the layout.

A direct Google Docs file or `.gdoc` shortcut may not behave like an exported document, depending on how you are adding it. When in doubt, export the file.

### Clean files work better than fancy files

The most important thing is not the file format. It is whether GPT can understand what the file is.

A clean source document has:

* a clear title;
* obvious headings;
* short sections;
* labels that explain what each part is for;
* examples that are clearly marked as examples;
* templates that are clearly marked as templates;
* no huge unrelated text dumps.

For example, this is easy to understand:

```markdown
# Outfit Note Template

Use this when creating compact pinned-memory outfit notes.

## Include
- clothing
- colors/materials
- accessories
- hair/makeup if relevant
- scene or season
- how the outfit affects the character’s presence

## Output format
[Character] wears [outfit description]. The look feels [vibe] and supports [scene purpose].
```

This is harder:

```text
outfits maybe:
black dress
winter thing??
boots
remember the red coat idea from that one chat
also maybe use this for images sometimes
idk
```

Messy notes are fine in a chat. Source documents should be cleaner because you want GPT to reuse them later.

### Screenshots and images

Screenshots can be useful when the visual appearance matters. For example, you might use screenshots for clothing inspiration, character references, room layouts, or interface examples.

But screenshots are usually not the best way to provide text-heavy instructions, templates, or checklists.

If the file is mostly words, use a text document when possible. A clean `.txt`, `.md`, `.docx`, or exported `.pdf` is usually better than a screenshot of text.

Use screenshots for visual reference. Use text files for instructions.

### A clean file checklist

Before relying on a source document, check:

* Does the file have a clear title?
* Can GPT tell what the file is for?
* Are the headings obvious?
* Are templates separated from examples?
* Are old notes removed or clearly labeled?
* Is the document short enough to use easily?
* Does it avoid unrelated lore or random scraps?
* Would another person understand how to use it?

If the answer is yes, it is probably a useful source document.

If the answer is no, clean it up before adding more files.

### How to ask GPT to use an uploaded file

When using a file, name it and give it a job.

Example:

```text
Use the uploaded file named `Basic Character Checklist` as reference for this task. Follow its structure where relevant. If something important is missing, mark it as a question instead of inventing major details.

Here is my rough character idea:

[PASTE IDEA]
```

Another example:

```text
Use `Outfit Note Template` as the output format. Create a pinned-memory outfit note for this character and scene:

Character: [NAME]
Scene: [SCENE]
Style goal: [VIBE]
Required details: [DETAILS]
```

This is better than simply uploading a file and saying:

```text
Use this.
```

GPT may not know whether “use this” means follow the exact format, borrow the style, check for consistency, summarize it, or use it as background reference.

Tell the file what job it has.

### Keep files practical

A source document is useful when it helps GPT do a job.

It does not need to be beautiful. It does not need to be comprehensive. It does not need to explain your entire creative universe.

For a beginner, the best files are usually small and boring in a good way:

* a preference note;
* a checklist;
* a template;
* a list of reusable prompts;
* a setting note.

Those files are easy to update and easy for GPT to use.

Start there.

## 6. How to write a basic prompt

A useful prompt does not need magic wording.

You do not need to sound technical. You do not need to know prompt-engineering terms. You do not need to write a giant instruction block every time you ask for help.

A good beginner prompt usually does four things:

1. tells GPT what you are making;
2. shows what you already have;
3. says what kind of help you want;
4. says what should not be changed or lost.

That is the heart of prompting.

You are not casting a spell. You are giving GPT a job.

### A simple prompt pattern

Here is a reusable pattern you can copy, paste, and fill in:

```text
I’m making: [what you are making]

Here’s what I have: [rough idea / draft / notes]

What I want help with: [brainstorm / plan / draft / revise / review]

What I want preserved: [specific idea, tone, weird detail, relationship, etc.]

Use this source/template if relevant: [file name]

Give the answer as: [list, outline, draft, table, questions, etc.]
```

You do not need to fill in every line every time. Use the parts that matter.

If you are brainstorming, the source/template line may not matter. If you are asking GPT to follow a checklist, the source/template line matters a lot. If you are asking for review, the “what I want preserved” line helps GPT avoid rewriting the entire idea into something smoother but less yours.

### What each part does

**“I’m making…”** tells GPT the kind of creative task you are doing.

Examples:

```text
I’m making an OurDream character.
```

```text
I’m making a persona for a fantasy romance chat.
```

```text
I’m planning a group chat with three characters.
```

```text
I’m making a pinned-memory outfit note.
```

This helps GPT choose the right kind of answer.

**“Here’s what I have…”** gives GPT the material to work with.

This can be polished or messy. Both are fine.

Examples:

```text
Here’s what I have: a goth vampire college student who works night shifts at the campus library.
```

```text
Here’s what I have: a rough draft of her public description, but it feels generic.
```

```text
Here’s what I have: three characters I want in a group chat, but I do not know why they are together.
```

GPT works better when it has something concrete to react to. Even a rough seed is better than a blank request.

**“What I want help with…”** tells GPT the mode of help.

This is one of the highest-value parts of a prompt. “Help me with this character” can mean many different things. Do you want brainstorming? A plan? A draft? A review? A rewrite?

Name the job.

### Five useful prompt modes

For beginner OD creation work, these five modes cover a lot:

| Mode       | Use it when                          | Example ask                                       |
| ---------- | ------------------------------------ | ------------------------------------------------- |
| Brainstorm | You want possibilities               | “Give me 5 different directions.”                 |
| Plan       | You want structure before drafting   | “Help me organize this into a character concept.” |
| Draft      | You want usable text                 | “Draft a short public description.”               |
| Revise     | You want to improve existing text    | “Make this clearer but preserve the tone.”        |
| Review     | You want feedback before changing it | “Tell me what works and what feels generic.”      |

These modes can be combined, but beginners usually get better results by starting with one.

For example, instead of asking:

```text
Make this character better.
```

Try:

```text
Review this character idea before rewriting it. Tell me what is working, what feels generic, and what decisions I should make before drafting.
```

That gives GPT a clearer job.

### Tell GPT what to preserve

This is especially important for creative work.

GPT is often good at making something sound smoother. That does not always mean it made the idea better. Sometimes the smoother version loses the weird, specific, or emotionally interesting part.

If something matters, say so.

Examples:

```text
Preserve the idea that she is sweet but unsettling.
```

```text
Do not remove the small-town Southern Gothic tone.
```

```text
Keep the character’s loneliness central, but do not make her helpless.
```

```text
The funny part is that she treats supernatural events like normal office problems. Preserve that.
```

This helps GPT improve the idea without sanding off its shape.

### Tell GPT what format you want back

If you want a list, ask for a list. If you want a table, ask for a table. If you want copy/paste text, ask for copy/paste text.

Examples:

```text
Give me 5 options, each with a short explanation.
```

```text
Give me a compact outline, not a full draft.
```

```text
Give me paste-ready text.
```

```text
Give me questions only. Do not draft yet.
```

```text
Give me a table comparing the options.
```

This is a simple way to make the answer easier to use.

### Bad / better example

A vague prompt can still work, but it gives GPT more room to guess.

Less useful:

```text
Make me a vampire girl character.
```

Better:

```text
I’m making an OurDream character from this seed:

A goth vampire college student.

I want help brainstorming, not drafting yet. Give me 5 different directions that make her less generic. Preserve the goth/vampire/college seed, but vary her motive, social life, roleplay appeal, and first-scene possibilities.
```

The better prompt does not need fancy wording. It is better because it gives GPT a clearer task.

It says:

* what the user is making;
* what the seed is;
* what kind of help they want;
* what must be preserved;
* what kind of variation would be useful;
* what not to do yet.

That is enough.

### Ask for less than everything

One of the easiest beginner mistakes is asking GPT for a full finished character too early.

Sometimes that is fine. But if your idea is still loose, a full draft can skip important decisions. GPT may fill in the blanks with obvious defaults, and then those defaults can start to feel more “official” than they should.

Try asking for smaller steps first:

```text
Do not draft the full profile yet. Help me decide what this character is about.
```

```text
Give me 5 possible roleplay engines for this idea.
```

```text
Ask me the 5 most useful questions before we draft.
```

```text
Review this idea for what feels generic before improving it.
```

Smaller prompts often lead to better final drafts because you make the creative decisions before GPT starts filling space.

### A simple default workflow

When you are not sure what to do, use this order:

1. brainstorm;
2. choose a direction;
3. plan;
4. draft one piece;
5. review;
6. revise.

For example:

* Brainstorm five versions of a character.
* Pick one version.
* Ask GPT to plan her core appeal, personality, voice, and first scene.
* Draft only the public description or greeting.
* Ask GPT to review that draft.
* Revise it.

You do not have to use this every time. It is just a reliable beginner path.

The main idea is simple: do not make GPT jump to the final answer before you know what answer you want.

## 7. Meta-prompting: ask GPT to help you ask better

Meta-prompting means asking GPT to help you write, improve, or choose the prompt before doing the main task.

That sounds more technical than it is.

The beginner version is:

> If you do not know how to ask for what you want, ask GPT to help you ask.

This is one of the most useful habits you can learn.

You do not need to know the right words upfront. You can start with a messy explanation and ask GPT to turn it into a clearer request.

### Why meta-prompting helps

Many people get stuck because they think they need to already know how to prompt.

They have a character idea, but they are not sure whether to ask for brainstorming, a draft, a profile, a checklist, questions, or review. Or they have a template, but they are not sure how to tell GPT to follow it. Or they know something is wrong with a character, but they do not know how to describe the problem.

Meta-prompting helps because it lets GPT help with the setup.

Instead of asking for the final answer, you ask for the better question.

That can save a lot of frustration.

### When to use meta-prompting

Use meta-prompting when:

* your idea is messy;
* you do not know what kind of help to ask for;
* you are not sure whether you need brainstorming, planning, drafting, revising, or review;
* you want GPT to use a template or source document;
* you want GPT to ask questions before drafting;
* GPT keeps giving answers that are too broad;
* you want a reusable prompt for a task you do often.

A good meta-prompt can be very short.

```text
Help me turn this messy idea into a clear prompt.
```

```text
What information should I give you before asking you to draft this?
```

```text
Ask me the minimum useful questions before we start.
```

```text
I want to use the attached template. Write a prompt that tells GPT to follow it without inventing missing details.
```

```text
Before answering, help me choose whether I need brainstorming, planning, drafting, or review.
```

These are not advanced tricks. They are just ways to slow down before the main task.

### A useful stuck prompt

When you are overwhelmed, try this:

```text
I want help with this OurDream creation task, but I’m not sure how to ask for it.

Here is what I’m trying to do:

[DESCRIBE TASK OR IDEA]

Help me write a clear prompt. Keep it beginner-friendly. Make sure the prompt tells GPT what to preserve, what kind of help to give, and what format to answer in.
```

This works because you are not asking GPT to solve the creative problem yet. You are asking it to help frame the problem.

### Example: messy idea into clearer prompt

Messy starting point:

```text
I want to make a character who is like a vampire college girl but not boring and maybe she works at a library or something and is kind of lonely but I don’t want her to just be shy and sad. I don’t know what to ask.
```

A meta-prompt could be:

```text
Help me turn this messy OurDream character idea into a clear prompt. I want GPT to preserve the goth vampire college student idea, the library angle, and the loneliness, but I do not want the character to become a generic shy sad girl. The prompt should ask for brainstorming options, not a full profile yet.
```

GPT might turn that into:

```text
I’m making an OurDream character from this rough seed:

A goth vampire college student who works at the campus library. She is lonely, but I do not want her to become a generic shy sad girl.

Help me brainstorm 5 distinct directions for her. Preserve the vampire, college, library, goth, and loneliness elements. For each direction, give her a different motive, social role, source of conflict, and roleplay appeal. Do not draft the full profile yet.
```

That final prompt is much easier to use.

It tells GPT what to preserve. It names the risk. It asks for options. It avoids jumping straight into a full draft.

### Meta-prompting with source documents

Meta-prompting is also useful when you have a source document or template.

Instead of guessing how to use it, ask GPT to help create the prompt.

```text
I have a source document called `Basic Character Checklist`. I want GPT to use it to help develop this rough character idea:

[PASTE IDEA]

Write a prompt that tells GPT to use the checklist as a planning structure, preserve my idea, and mark missing information as questions instead of inventing major facts.
```

This is especially helpful if you are using a template for the first time.

A template can be used in different ways: strict format, loose checklist, review guide, example style, or reference. The meta-prompt helps you decide what role the template should play.

### Meta-prompting for reusable prompts

If you notice yourself doing the same kind of task repeatedly, ask GPT to help turn it into a reusable prompt.

```text
I keep asking for help with this workflow:

[DESCRIBE WORKFLOW]

Help me turn it into a reusable prompt. Keep it simple enough for a beginner. Include placeholders I can fill in later.
```

For example, you might create reusable prompts for:

* brainstorming a character;
* reviewing a public description;
* making pinned-memory outfit notes;
* planning a group chat;
* designing a home or setting;
* turning messy notes into a clean concept.

Save the prompts that work in your `Reusable Prompts` source document.

### The most important meta-prompting rule

When you feel stuck, do not ask for the final answer first.

Ask GPT to help you make the request.

That one habit can make everything else easier.

## 8. Using GPT for character ideas

Character ideas are one of the easiest places to start using GPT.

You do not need a finished concept. You do not need a complete profile. You do not need to know every OurDream field before asking for help.

A rough seed is enough.

The important thing is to help GPT preserve what matters instead of turning your idea into the most obvious version of itself.

### Start with the seed

A seed is the small starting idea you already have.

Examples:

* a goth vampire college student;
* a retired magical girl running a laundromat;
* a demon accountant who treats contracts like customer service;
* a knight who is more afraid of court politics than battle;
* a cozy witch who runs a cafe for ghosts;
* a werewolf roommate who is terrible at hiding obvious supernatural problems.

A seed can be simple, silly, dramatic, romantic, strange, or incomplete. That is fine.

The first job is not to make it perfect. The first job is to understand what makes it interesting.

Ask GPT to identify the appeal before improving it.

```text
Here is my rough character seed:

[PASTE SEED]

Before suggesting changes, tell me what seems most interesting about this idea and what should probably be preserved.
```

That prompt protects your idea from being overwritten too quickly.

### Ask for options before a full draft

When you ask for a full character immediately, GPT has to make a lot of decisions for you.

Some of those decisions may be useful. Others may be generic defaults.

That is why options are often better early on.

Instead of:

```text
Make me a full character profile for a goth vampire college student.
```

Try:

```text
I’m making an OurDream character from this rough seed:

A goth vampire college student.

First identify what seems most interesting about the seed. Then give me 5 different development directions. Do not draft the full profile yet. Preserve the goth/vampire/college idea, but make the directions meaningfully different.
```

This gives you choices.

Maybe one version is a campus librarian’s assistant hiding from an old vampire family. Another is a biology major studying her own undeath. Another is a theater kid using vampire mystique as social armor. Another is a lonely commuter student who treats immortality like an academic scheduling problem.

You may not use any option exactly. That is fine. The point is to create useful possibilities.

### Tell GPT what must not be erased

If the seed has a detail you care about, say so.

Examples:

```text
Preserve the fact that she is funny in a dry, tired way.
```

```text
Do not make her elegant and ancient. I want her to feel like an actual stressed college student.
```

```text
Keep the library job central. It should not become a random background detail.
```

```text
Do not make loneliness her whole personality.
```

This is especially useful when your idea uses a familiar archetype. GPT knows many familiar patterns. If you do not give it a sharper direction, it may reach for the easiest one.

A vampire may become seductive and ancient. A shy character may become helpless. A goth character may become all aesthetic and no motive. A confident character may become arrogant. A caring character may become a therapist.

If you know the obvious version is not what you want, say so.

### Starter prompt: brainstorm from a rough seed

```text
I’m making an OurDream character from this rough seed:

[PASTE SEED]

First identify what seems most interesting about the seed. Then give me 5 different development directions. Do not draft the full profile yet. Preserve the specific or weird part of the idea.
```

Use this when:

* the idea is new;
* you want options;
* you do not want GPT to decide everything yet.

### Starter prompt: improve without replacing the idea

```text
Here is my current character idea:

[PASTE IDEA]

Review it for clarity, distinctiveness, and roleplay usefulness. Preserve the specific or weird part of the idea. Do not rewrite the whole thing yet. Give me:
1. what is already working;
2. what feels generic or underdeveloped;
3. 5 specific improvements I could choose from;
4. any questions that would materially improve the character.
```

Use this when:

* you already have an idea;
* it feels close but not strong yet;
* you want critique without losing control of the concept.

This prompt is useful because it asks for review before rewrite.

### Starter prompt: review before drafting

```text
Before drafting this character, help me understand the concept.

Here is the idea:

[PASTE IDEA]

Tell me:
1. what the core appeal seems to be;
2. what should be preserved;
3. what could make the character more distinct;
4. what might become generic if handled poorly;
5. what information is still missing before drafting.
```

Use this when:

* you are tempted to ask for a full profile;
* the concept still feels fuzzy;
* you want to make a few creative decisions first.

This is often a better step than drafting immediately.

### Example: goth vampire college student

A weak prompt:

```text
Make me a goth vampire college student.
```

A stronger prompt:

```text
I’m making an OurDream character from this rough seed:

A goth vampire college student who works late shifts in the campus library.

I do not want her to be a generic seductive ancient vampire or a generic shy sad goth girl. Preserve the college-life stress, the library angle, the vampire problem, and a dry sense of humor.

Give me 5 different development directions. For each, include:
- her main motive;
- what makes her fun to interact with;
- what could create scenes;
- what makes her more specific than the basic archetype.

Do not draft the full profile yet.
```

This prompt gives GPT much more to work with.

It does not overcomplicate the request. It just gives the seed, the preservation points, the generic versions to avoid, and the kind of output wanted.

### Ask what could go generic

This is a very useful character-development question:

```text
What is the most generic version of this character idea, and how can I avoid it while keeping the original appeal?
```

You can also ask:

```text
What would make this character feel interchangeable with similar characters?
```

```text
What are 5 details that would make this character more specific in actual roleplay?
```

```text
What should this character do in chat that makes them feel distinct?
```

That last question matters. A character is not only a description. On OurDream, the character needs to do something in play: respond, choose, notice, resist, initiate, misunderstand, care, tease, hide, reveal, pursue, avoid, or create scenes.

A good character idea should eventually answer:

> What is fun, interesting, tense, comforting, dramatic, or emotionally engaging about interacting with this character?

GPT can help you find that answer.

### Do not draft everything at once

A full character profile can come later.

Early on, it is often better to draft one piece at a time:

* core concept;
* public description;
* greeting idea;
* personality notes;
* voice examples;
* setting;
* relationship premise;
* first scene.

That makes it easier to notice when something is off.

For example:

```text
Using the direction I chose, draft only a short public-facing character concept. Do not draft hidden details yet.
```

Or:

```text
Now help me plan the first scene for this character. Give me 3 possible openings and explain what each one invites the user to do.
```

Smaller steps give you more control.

### A default character workflow

When in doubt, use this simple workflow:

1. **Brainstorm:** generate several directions.
2. **Choose direction:** pick or combine the best parts.
3. **Plan:** identify core appeal, motive, voice, setting, and first scene.
4. **Draft one piece:** public description, greeting, persona note, or another small section.
5. **Review:** ask what works and what might be generic or unclear.
6. **Revise:** improve the draft while preserving the chosen idea.

This workflow is slower than “make me a full character,” but it often gives better results.

It also keeps you in charge.

GPT can help you explore the idea, but you decide what survives.

## 9. Using GPT for user personas

GPT can help turn rough User Persona notes into compact, usable OurDream continuity.

The main job is not to make a full backstory. It is to give OurDream stable details about the user-side protagonist so characters can recognize, reference, and react to them consistently. Good Persona details are things characters could plausibly notice, infer, ask about, or comment on in play.

### What to give GPT

A beginner does not need perfect notes. Start with whatever is known, such as:

* name or handle;
* pronouns or gender;
* age or life stage;
* ancestry, species, or ethnicity if relevant;
* appearance baseline;
* face, voice, movement, scent, or grooming cues;
* home, work, schedule, or routine anchors;
* stable relationship anchors;
* capabilities, limits, resources, or gear for fantasy, sci-fi, supernatural, or nonhuman personas.

Not every Persona needs every category. A realistic modern Persona may only need appearance, home, work, and routine anchors. A fantasy Persona may need species, social role, gear, and limits. A sci-fi Persona may need ship role, faction, implants, mobility, or tech access.

The useful question is:

> What stable details would help OurDream maintain continuity?

### What to ask GPT for

GPT can help by:

* organizing messy notes;
* identifying what is stable enough to include;
* trimming backstory clutter;
* making details more mentionable;
* turning vague traits into visible continuity anchors;
* producing a compact paste-ready Persona;
* asking concise questions when important details are missing.

A good Persona should stay compact, usually around or under 2,500 characters. It should not become a diary, full biography, plot outline, wardrobe catalog, or scene plan.

### Starter prompt: create a User Persona

```text
Help me create an OurDream User Persona from these notes:

[PASTE NOTES]

The Persona should tell OurDream who the user is roleplaying so characters can maintain continuity and react to stable details.

Focus on compact, mentionable canon:
- core identity;
- appearance baseline;
- voice, movement, scent, or grooming cues;
- home, work, schedule, and routine anchors;
- stable relationship anchors;
- capabilities, limits, resources, or gear if this is fantasy, sci-fi, supernatural, or nonhuman.

Keep it around or under 2,500 characters. Do not make it a full backstory, diary, plot outline, wardrobe catalog, or scene plan. If important details are missing, ask concise questions or mark them as unspecified.
```

Use this when there are rough notes but not a clean Persona yet.

### Starter prompt: review a User Persona

```text
Review this OurDream User Persona:

[PASTE PERSONA]

Tell me:
1. what provides useful stable canon;
2. what characters could plausibly notice, infer, comment on, or reference;
3. what is too vague, too long, or too diary-like;
4. what feels like backstory clutter instead of reusable Persona detail;
5. what should be trimmed or clarified;
6. a compact revised version around or under 2,500 characters.
```

Use this when a Persona feels too long, too vague, or more like a biography than a useful continuity reference.

### Short example

Useful Persona detail:

```text
Morgan Vale is a junior archivist at Blackbriar University Library. They know the restricted stacks better than most students. Morgan is in their late twenties, has a quiet voice, ink-smudged fingers, and a habit of checking exits when rooms get too crowded.
```

This works because it gives OurDream stable details characters can use: Morgan’s role, age/life stage, library familiarity, voice, ink stains, and visible habits. It creates continuity hooks without becoming a full backstory.

### Simple rule

Use GPT to turn messy Persona notes into compact, mentionable continuity.

If a detail will not help characters recognize, reference, or respond to the persona, it probably does not need to be in the Persona field.

## 10. Using GPT for group chats

Group chats are different from solo character chats because the scene has more moving parts.

In a solo chat, the main question is usually:

> Why is this character interesting to interact with?

In a group chat, you also need to ask:

> Why are these characters together, and what does each one add?

Group chats usually need a little more planning than solo chats because GPT has to balance multiple characters, relationships, and possible directions. Every character should have a reason to be present.

### A simple group chat planning checklist

Before drafting a group chat, ask:

* Which characters are included?
* Why are these characters in the same place or situation?
* What does each character contribute?
* What does each character want, avoid, or misunderstand?
* What is the user’s possible role?
* What is the opening situation?
* What tension, chemistry, task, event, or shared location creates movement?
* What should stay flexible?

This prevents the group chat from becoming several characters standing around waiting for the user.

### Starter prompt: plan a group chat

```text
I want to make an OurDream group chat using these characters:

[LIST CHARACTERS + SHORT NOTES]

Help me plan the group chat setup. Focus on:
1. why these characters are together;
2. what each character contributes;
3. what tensions, chemistry, or shared goals exist;
4. what the user’s role can be;
5. what the opening situation should be;
6. what should stay flexible.

Do not draft final field text yet.
```

### Starter prompt: review a group chat idea

```text
Review this group chat idea:

[PASTE IDEA]

Tell me:
1. whether every character has a reason to be present;
2. whether the user has a clear way to enter the scene;
3. what conflict, chemistry, or shared activity can create motion;
4. what might become confusing;
5. the smallest useful improvements.
```

### What each character contributes

One high-yield question is:

> What does each character add that the others do not?

One character might create warmth. Another might create conflict. Another might know the setting. Another might resist the obvious solution. They do not need rigid jobs, but if two characters do the exact same thing in the scene, one of them may disappear or blur.

Useful prompts:

```text
For each character in this group chat, tell me what they contribute to the scene that the others do not.
```

```text
Which character is most likely to get overshadowed in this group setup, and how can I give them a clearer reason to be present?
```

### Give the user a way in

A group chat also needs a user entry point. That does not mean the user must be the center of everything. It just means the user should have a clear way to participate.

Examples:

* The user is invited to the dinner.
* The user is the new roommate.
* The user owns the shop where everyone gathers.
* The user is part of the adventuring party.
* The user is caught in the same storm, delay, festival, investigation, or crisis.
* The user is connected to one character and unfamiliar to the others.

If the group chat has no obvious user entry, the opening may feel like a scene already happening behind glass.

### Keep some things flexible

A group chat setup should define the starting situation and the relationships that matter. It does not need to decide every outcome.

Useful fixed details include who is present, where they are, why they are there, and what starts the scene. Useful flexible details include who the user bonds with most, which conflict becomes central, which character takes focus first, and how the group changes over time.

## 11. Using GPT for outfits and pinned memories

GPT can also help with outfits and pinned memories.

This is a smaller workflow than making a whole character, but it can be very useful. A good outfit note can help keep a character’s look consistent for a specific scene, season, event, or alternate version.

An outfit note for roleplay continuity is not the same thing as an image prompt.

### Outfit note vs image prompt

An outfit note is usually compact. It helps the chat remember what the character is wearing and how that affects the scene.

An image prompt is usually more visual and detailed. It may include composition, lighting, art style, camera angle, rendering details, or image-specific instructions.

For this guide, focus on outfit notes first.

A roleplay outfit note should answer:

* What are they wearing?
* What visual details matter?
* Why does this outfit fit the scene?
* How does it affect their presence?

### A simple outfit note checklist

Before asking GPT for an outfit note, give it:

* character name;
* scene, season, event, or situation;
* style goal or vibe;
* required clothing pieces;
* colors and materials;
* accessories;
* hair or makeup if relevant;
* practical details;
* what should stay consistent;
* what to avoid.

### Starter prompt: create an outfit note

```text
Help me create a pinned-memory outfit note for this character:

Character: [NAME]
Situation: [SCENE / EVENT / SEASON]
Style goal: [VIBE]
Must include: [DETAILS]
Avoid: [DETAILS]

Write a compact outfit note that includes clothing, colors/materials, accessories, hair/makeup if relevant, and how the outfit affects their presence in the scene. Keep it practical for roleplay continuity.
```

### Starter prompt: revise an outfit note

```text
Review this outfit note:

[PASTE OUTFIT NOTE]

Make it clearer and more compact for a pinned memory. Preserve the important visual details, remove clutter, and keep the roleplay-relevant presence.
```

### Example compact outfit note

```text
Maren wears a charcoal wool coat over a soft cream sweater, dark jeans, and weathered brown ankle boots. A deep red scarf adds warmth and color, and her hair is loosely pinned back with a few wind-tossed strands around her face. The look feels practical, winter-warm, and quietly elegant, making her seem prepared without looking formal.
```

This is enough for many roleplay uses. It gives clothing, colors, materials, a small hair detail, and the character’s presence without becoming a full wardrobe essay.

### Do not overbuild every outfit

If the note is for a pinned memory, it should usually be compact. The point is to help continuity, not bury the chat in visual detail.

A simple rule:

> Describe the details that change the scene. Cut the details that only decorate the note.

## 12. Using GPT for homes, cities, and settings

Settings are one of the easiest things to overbuild.

It is fun to make maps, lore, neighborhoods, room descriptions, factions, histories, and hidden secrets. GPT can help with all of that. But for beginner roleplay use, the most important question is simpler:

> What can happen here?

A good setting gives characters something to do.

### Roleplay-useful detail vs lore-dump detail

Roleplay-useful detail gives the chat something to use.

Examples:

* the kitchen table is the only clean surface in the apartment;
* the cafe has a back booth where regulars leave notes under the sugar jar;
* the city’s old tram line still runs once a night with no listed driver;
* the school greenhouse is warm, private, and technically off-limits after dusk;
* the tavern owner knows everyone’s business but pretends not to.

These details create action, mood, privacy, conflict, or opportunity.

Lore-dump detail may be interesting, but it does not always help the scene. A long list of rulers, districts, or rooms is only useful if the characters have a reason to care.

### A simple setting checklist

When planning a setting, ask:

* What type of setting is it?
* Who uses it?
* What tone or vibe should it have?
* What are the key rooms, places, or landmarks?
* What sensory details matter?
* What happens here on an ordinary day?
* What social opportunities does it create?
* What conflict, pressure, or mystery could happen here?
* What can GPT invent later?
* What should stay fixed?

### Starter prompt: design a setting

```text
Help me design a roleplay setting for OurDream.

Setting type: [home / apartment / city / shop / school / fantasy town / etc.]
Character(s): [WHO USES IT]
Tone: [cozy / gothic / luxurious / chaotic / grounded / etc.]
Important themes: [THEMES]
Must include: [DETAILS]
Avoid: [DETAILS]

Give me:
1. the core concept;
2. 5–8 concrete places or details;
3. how the setting creates roleplay opportunities;
4. what should stay flexible for future chats.
```

### Starter prompt: review a setting

```text
Review this setting idea:

[PASTE SETTING]

Tell me:
1. what scenes this setting naturally supports;
2. what details feel vivid and useful;
3. what feels like lore that may not affect play;
4. what should be fixed versus left flexible;
5. 5 specific improvements.
```

### Different types of settings

GPT can help with many scales of setting:

* **Homes and apartments** support ordinary life, comfort, conflict, routines, and personal details.
* **Workplaces, shops, and schools** support recurring interactions, social pressure, secrets, rivals, customers, coworkers, and interruptions.
* **Cities, neighborhoods, and towns** support exploration, social networks, public reputation, and recurring locations.
* **Fantasy or sci-fi locations** support wonder, danger, rules, factions, travel, and discovery.
* **Recurring social spaces** help characters meet naturally, interrupt each other, overhear things, and create new scenes.

### Keep some details flexible

Not every detail needs to be fixed. Fixed details matter for continuity. Flexible details leave room for future invention.

Useful prompt:

```text
Separate this setting into fixed details and flexible details. Fixed details should matter for continuity. Flexible details can be invented later when useful.
```

When reviewing a setting, ask:

> What can characters do here?

If the answer is only “look at it,” the setting may need stronger scene handles: a broken heater, a locked room, a regular customer, a storm outside, a shared kitchen, a suspicious noise, a message board, or a place where people go when they do not want to be found.

## 13. Using GPT to review or improve a draft

GPT is not only useful for making new material. It can also help you review what you already wrote.

For many creators, this is one of the best uses of GPT because it keeps you in control. Instead of asking GPT to replace your draft, you ask it to help you understand the draft.

The simple principle is:

> Review before rewrite.

A review helps you see what is working, what is unclear, what feels generic, and what needs the smallest useful fix. A rewrite may improve the surface, but it can also erase the parts that made the draft yours.

### Review, revise, and rewrite

| Task | What it means | Use it when |
|---|---|---|
| Review | GPT gives feedback without changing the draft | You want to understand what works or does not work |
| Revise | GPT improves the draft while preserving the original intent | You know what needs fixing |
| Rewrite | GPT creates a new version more freely | You are okay with bigger changes |

For beginner use, review is often the best first step.

### A simple review checklist

When reviewing an OurDream draft, useful questions include:

* What is already working?
* What is unclear?
* What feels generic?
* What may be too long?
* What may be missing?
* What might be misunderstood in chat?
* What should be preserved?
* What should be fixed first?

### Starter prompt: review a draft before rewriting

```text
Review this OurDream draft for practical roleplay usefulness.

[PASTE DRAFT]

Do not rewrite it yet. Tell me:
1. what is already working;
2. what is unclear or underdeveloped;
3. what feels generic;
4. what might be misunderstood in chat;
5. what should be preserved;
6. the smallest useful fixes.
```

### Starter prompt: revise after review

```text
Using the review above, revise the draft.

Preserve:
[LIST WHAT MUST STAY]

Fix:
[LIST WHAT TO IMPROVE]

Do not add major new facts unless needed. Keep the revised version close to my original intent.
```

### Starter prompt: smallest useful fixes

```text
Give me the smallest useful patch for this draft. Do not rewrite the whole thing. Identify the exact sentence, paragraph, or idea that needs changing and provide a compact replacement.
```

### Bad / better example

Less useful:

```text
Make this better.
```

Better:

```text
Review this draft first. Tell me what works, what feels generic, what is unclear, and the smallest useful fixes. Do not rewrite yet.
```

The better prompt does not use fancy wording. It just names the job more clearly.

### Polished is not always better

GPT can make text sound smoother very quickly. That can be useful, but smooth text is not always stronger text.

A polished rewrite may accidentally remove the weird detail, make the character more generic, soften the tone too much, add backstory you did not intend, or make the roleplay premise less clear.

The best question is not always “Does this sound better?” Sometimes the better question is:

> Does this still do the job I wanted it to do?

## 14. Common beginner mistakes

Most beginner GPT mistakes are normal.

They usually happen because the creator is trying to get a useful answer, but the prompt or setup gives GPT too much room to guess. The fix is usually small: name the job, preserve the important part, and ask for the next useful step.

Use this section as a troubleshooting checklist.

### Mistake 1: Asking for a full finished character too early

**What it looks like:** “Make me a full OurDream character from this idea.”

**Why it causes problems:** If the idea is still rough, GPT has to make a lot of decisions for you and may fill the gaps with obvious defaults.

**Better habit:** Ask for brainstorming or planning first.

```text
I’m not ready for a full draft yet. Help me identify the core appeal, what should be preserved, and 5 possible directions for this character.
```

### Mistake 2: Not telling GPT what to preserve

**What it looks like:** “Improve this character idea.”

**Why it causes problems:** GPT may improve the surface while changing the part you cared about.

**Better habit:** Name the part that must survive.

```text
Improve this character idea, but preserve the strange cozy-horror tone, the character’s dry humor, and the fact that the setting feels ordinary until something is clearly wrong.
```

### Mistake 3: Uploading too many files too early

**What it looks like:** You upload old drafts, huge lore notes, templates, examples, screenshots, research files, and half-finished ideas before you know what job each file has.

**Why it causes problems:** More files do not automatically make GPT better. They can make it less clear which source should matter for a task.

**Better habit:** Start with one or two small files, such as `My OD Preferences`, `Basic Character Checklist`, or `Reusable Prompts`.

### Mistake 4: Making Project Instructions too long

**What it looks like:** Your Project Instructions become a giant rulebook with templates, examples, every preference, every workflow, and every edge case.

**Why it causes problems:** Long instructions are harder to maintain and easier to contradict.

**Better habit:** Keep Project Instructions for stable behavior guidance. Put templates, examples, and checklists in source documents.

### Mistake 5: Assuming GPT used a source document because it was uploaded

**What it looks like:** You upload a template, ask for a task, and assume GPT followed the template.

**Why it causes problems:** GPT may treat the source as background inspiration instead of a required structure.

**Better habit:** Name the file and give it a job.

```text
Use the uploaded file named `Basic Character Checklist` as the structure for this task. Follow its section order where relevant. If something important is missing, mark it as a question instead of inventing major facts.
```

### Mistake 6: Accepting the first polished answer as final

**What it looks like:** GPT gives a smooth answer, and you use it immediately because it sounds good.

**Why it causes problems:** Smooth text can hide weak choices.

**Better habit:** Ask for review after the first answer.

```text
Compare this draft against my original seed. What did it preserve, and what did it accidentally change?
```

### Mistake 7: Letting GPT make the idea flatter

**What it looks like:** Your original idea is sharp, strange, funny, intense, or specific. GPT turns it into something more broadly acceptable but less interesting.

**Why it causes problems:** Many character ideas are interesting because of their specific shape.

**Better habit:** Tell GPT the risk.

```text
The unusual part of this idea is important. Do not smooth it into a generic version. Help me make it clearer while keeping the strange specific hook.
```

### Mistake 8: Using examples as scripts

**What it looks like:** You see an example prompt, template, greeting, or description and treat it as the exact structure every future character must follow.

**Why it causes problems:** Examples are useful, but they are not universal.

**Better habit:** Ask what the example is doing, then apply that function to your own case.

```text
What is this example doing well, and how can I apply the same function to my different character without copying the shape?
```

### Mistake 9: Asking vague prompts like “make it better”

**What it looks like:** “Make this better.”

**Why it causes problems:** GPT has to guess what “better” means.

**Better habit:** Name the kind of improvement.

```text
Review this draft first. Tell me what works, what feels generic, what is unclear, and the smallest useful fixes. Do not rewrite yet.
```

### Mistake 10: Building a system instead of making one useful thing

**What it looks like:** You spend all your energy setting up Projects, files, templates, prompt lists, and instructions before testing whether any of it helps you create.

**Why it causes problems:** A system can feel productive while keeping you away from the actual creative work.

**Better habit:** Make one useful thing first. Then ask, “What would make this easier next time?”

### Three quick instead-of / try swaps

Instead of:

```text
Make this better.
```

Try:

```text
Review this draft first. Tell me what works, what feels generic, what is unclear, and the smallest useful fixes. Do not rewrite yet.
```

Instead of:

```text
Use my files.
```

Try:

```text
Use the file named `Basic Character Checklist` as a planning checklist. Follow it where relevant and mark missing information as questions.
```

Instead of:

```text
Make a full character from this seed.
```

Try:

```text
Before drafting, identify the core appeal of this seed, what should be preserved, and 5 different development directions.
```

## 15. When to add more complexity

More setup is not automatically better.

More files, more templates, more instructions, and more prompts can help if they solve real problems. They can also slow you down if you add them too early.

The principle is:

> Add complexity when it solves a repeated problem.

### Signs it may be time to add complexity

It may be time to add a new source document, reusable prompt, template, or instruction when:

* you repeat the same instruction in many chats;
* you reuse the same prompt often;
* you make similar characters, personas, settings, or outfit notes repeatedly;
* you need a consistent format;
* you keep correcting GPT the same way;
* you want a repeatable review process;
* you keep searching old chats for the same wording.

For example, if you often say “preserve the weird part of my idea and give me options before rewriting,” that may belong in your Project Instructions. If you often use the same prompt for character brainstorming, save it in `Reusable Prompts`. If you often ask for outfit notes in the same shape, make an `Outfit Note Template`.

### Signs not to add complexity yet

You may not need more setup if:

* you only used the idea once;
* you do not understand the template yet;
* you are adding files because they seem impressive;
* the setup is slowing you down;
* you have not tested a simple version;
* you are spending more time organizing prompts than using them;
* you cannot explain what job the new file does.

A file should have a job. A template should solve a repeated formatting or planning need. A Project Instruction should guide broad behavior across many chats.

### A simple upgrade path

Use this order:

1. Save a prompt that worked.
2. Turn repeated notes into a tiny source document.
3. Make a checklist for a repeated planning task.
4. Make a template when you need consistent output.
5. Only then consider a more specialized Project or Custom GPT.

### Starter prompt: turn a workflow into a reusable prompt

```text
I keep using GPT for this workflow:

[DESCRIBE WORKFLOW]

Help me turn it into a simple reusable prompt. Include placeholders I can fill in later. Keep it beginner-friendly.
```

### Starter prompt: decide where a note belongs

```text
I have this instruction or note:

[PASTE NOTE]

Help me decide whether it belongs in:
1. Project Instructions;
2. a source document;
3. a reusable prompt list;
4. only the current chat.

Explain the reasoning briefly and suggest the simplest useful placement.
```

A good answer should usually favor the smallest useful placement.

For example:

* Broad repeated behavior → Project Instructions.
* Template or checklist → source document.
* Reusable task wording → reusable prompt list.
* One-time detail → current chat.

### Do not upgrade away from creating

It is easy to make the setup the hobby. A good system makes creation easier. A bad system makes you feel like you need to do homework before you can create anything.

When in doubt, return to the simplest question:

> What is the next useful thing I want GPT to help me make?

Then ask for that.

## Closing section: A simple first-week practice plan

This first-week plan is optional. You do not need to follow it exactly. You can stop after any useful result. The point is to build one small habit at a time instead of trying to master everything upfront.

### Day 1: Create the Project

Make one Project for OurDream creation work. Add the short instruction block from section 1. Do not add a pile of files yet.

Goal for the day:

> Create the workspace.

### Day 2: Brainstorm one rough character seed

Use one rough idea and the character brainstorm prompt from section 8.

Goal for the day:

> Get one useful brainstorm.

### Day 3: Start `My OD Preferences`

Create a tiny preference note using the mini-template in section 4. Do not try to make it complete.

Goal for the day:

> Give GPT a little more of your taste.

### Day 4: Use meta-prompting once

Take a task you are unsure how to ask for and use one of the meta-prompts from section 7.

Goal for the day:

> Let GPT help you make the prompt.

### Day 5: Review one draft

Pick something you already have: a character idea, public description, greeting, persona, group chat setup, outfit note, or setting. Use the review-before-rewrite prompt from section 13.

Goal for the day:

> Understand the draft before changing it.

### Day 6: Save one reusable prompt

Look back at the week. If any prompt worked well, save it in a file called `Reusable Prompts`.

Goal for the day:

> Keep one thing that worked.

### Day 7: Decide the next upgrade

Do not add everything. Ask what single addition would help next time: a source document, checklist, template, reusable prompt, or Project Instruction update.

Possible answers:

* Add a character checklist.
* Make an outfit note template.
* Save a group chat planning prompt.
* Expand `My OD Preferences`.
* Do nothing yet and keep practicing.

Doing nothing can be the right answer. If the simple setup is already helping, keep using it before adding more.

Goal for the day:

> Add only what would help next time.

### Final reminder

You do not need a perfect setup to start. You need one useful result, then another.

GPT can help you brainstorm, organize, draft, review, and revise. It can help you ask better questions. It can help you notice weak spots. It can help you turn messy ideas into something easier to work with.

But the creative direction is still yours.

Preserve the part of the idea that made you want to create it in the first place.
